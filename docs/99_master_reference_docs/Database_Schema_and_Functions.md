## 🗄️ Database Tables Summary

The Nonna PostgreSQL database consists of **25 active tables** structured into domain areas:

| Table Name | Domain | Purpose |
| ---------- | ------ | ------- |
| `profiles` | Identity | Extended user profiles linked to Supabase Auth (`auth.users`). |
| `user_stats` | Gamification | Tracks participation metrics and social scores per user. |
| `baby_profiles` | Milestones | Core profiles representing the babies being tracked. |
| `baby_memberships` | Access | Core Role-Based Access Control (RBAC) linking users to baby profiles with active roles (`owner`, `follower`). |
| `invitations` | Access | Secure, token-based email invitations generated by baby owners to add followers. |
| `owner_update_markers` | Tile Engine | Synchronization timestamps assisting offline-first cache invalidation. |
| `photos` | Media | Records for uploaded baby photos/videos, storing storage paths and metadata. |
| `photo_squishes` | Media | Social "likes" (squishes) on photo assets. |
| `photo_comments` | Media | Comment threads on specific photo assets. |
| `photo_tags` | Media | Tags mapping baby tags to photo assets. |
| `events` | Calendar | Calendar milestones and event scheduling records for babies. |
| `event_comments` | Calendar | Comment threads on specific calendar events. |
| `event_rsvps` | Calendar | RSVP attendance tracking for events. |
| `registry_items` | Registry | Wishlist/registry items created by owners. |
| `registry_purchases` | Registry | Markings indicating which item was purchased by which follower (single-purchase constraint). |
| `votes` | Gamification | Gender and birthdate prediction votes submitted by followers before birth. |
| `name_suggestions` | Gamification | Baby name recommendations proposed by family members. |
| `name_suggestion_likes`| Gamification | Votes/likes on proposed baby names. |
| `notifications` | Alerts | In-app notification alerts and delivery payload history. |
| `notification_preferences`| Alerts | Fine-grained push and email channel settings per user. |
| `screens` | Tile Engine | Definitions mapping supported screens in the app (e.g., `home`, `calendar`). |
| `tile_definitions` | Tile Engine | Definitions representing all 18 valid custom tile types. |
| `tile_configs` | Tile Engine | Position, visibility, and parameter setups for widgets on specific screens per user role. |
| `activity_events` | Activity | Audit events logging baby activity metrics for recap displays. |
| `app_versions` | Management | Version enforcement config specifying the minimum required app version per platform. |

## 📋 Comprehensive Table Column Definitions

### 1. User Identity Domain

#### `profiles`
Links user account metadata to Supabase Auth.
* **Row Level Security (RLS)**: Users can read all profiles; write access is restricted to the owning user.

| Column | Type | Constraints | Description & Usage |
|---|---|---|---|
| `user_id` | uuid | PRIMARY KEY, FK(`auth.users`) | Matches the underlying Supabase Auth user ID. |
| `display_name` | text | | User's chosen display name or nickname. |
| `avatar_url` | text | | Path/URL to the user's profile avatar. |
| `biometric_enabled` | boolean | DEFAULT false | Flags if the user enabled local biometric sign-in. |
| `created_at` | timestamptz | NOT NULL DEFAULT now() | Profile creation timestamp. |
| `updated_at` | timestamptz | NOT NULL DEFAULT now() | Last update timestamp. |

#### `user_stats`
Maintains gamification aggregate statistics.
* **Realtime**: Aggregated automatically via database trigger functions.

| Column | Type | Constraints | Description & Usage |
|---|---|---|---|
| `user_id` | uuid | PRIMARY KEY, FK(`auth.users`) | Matches the underlying Supabase Auth user ID. |
| `events_attended_count`| int | DEFAULT 0 | Count of events marked with a 'yes' RSVP. |
| `items_purchased_count`| int | DEFAULT 0 | Total number of registry items gifted. |
| `photos_squished_count`| int | DEFAULT 0 | Total number of photos squished (liked). |
| `comments_added_count` | int | DEFAULT 0 | Total photo and event comments written. |
| `updated_at` | timestamptz | NOT NULL DEFAULT now() | Last statistic aggregation update. |

#### `baby_memberships`

|---|---|---|---|

#### `registry_purchases`
Gift claims committed by family followers.

| Column | Type | Constraints | Description & Usage |
|---|---|---|---|
| `id` | uuid | PRIMARY KEY, DEFAULT gen_random_uuid() | Purchase entry ID. |
| `registry_item_id` | uuid | NOT NULL, UNIQUE, FK(`registry_items`) | Target registry item. |
| `purchased_by_user_id`| uuid | NOT NULL, FK(`auth.users`) | Gift giver user ID. |
| `purchased_at` | timestamptz | NOT NULL DEFAULT now() | marking bought timestamp. |
| `note` | text | | Optional message to child's parents. |

*Single-Purchase Constraints (Database Layer)*:
* Enforced via a strict **Unique Index** `uq_registry_purchases_registry_item_id` preventing multiple purchases of the same item.
* INSERT calls are validated through RLS checks ensuring that no other purchase entry exists for the target item.
* *Owner Deletion Policy*: Owners can execute a `DELETE` call on ANY registry purchase for their baby profile, allowing them to reset claimed gifts.

## ⚡ Serverless Edge Functions

Supabase Edge Functions are deployed under `supabase/functions/` to execute secure server-side logic, external API integrations, and image processing tasks.

### 1. `tile-configs`
* **Purpose**: Fetches dynamic configurations for the Dynamic Tile Engine.
* **Usage**: Accepts `{babyProfileId, userRole, screenName}` and returns sorted tile configurations joined with `screens` and `tile_definitions`.
* **Details**: Evaluates content-aware filters (like `hideWhenEmpty`) using data probes. If a tile is empty and has the `hideWhenEmpty` parameter set, it is filtered out from the final JSON delivery. Consumed directly by the Flutter `TileFactory` client wrapper.

### 2. `send-push-notification`
* **Purpose**: Dispatches push alerts via the **OneSignal REST API**.
* **Usage**: Resolves target user profiles, fetches notification preference toggles, and handles delivery payloads.
* **Details**: Invoked asynchronously by database triggers (e.g., when a photo is uploaded or a comment is posted).

### 3. `send-invitation-email`
* **Purpose**: Triggers HTML email invitations via the **Resend API**.
* **Usage**: Generates a secure token hash, inserts a record into the `invitations` table, templates the invitation email, and sends the deep link to the follower.

### 4. `generate-thumbnail`
* **Purpose**: Automated background downsizing for media files.
* **Usage**: Triggers upon uploads to the Supabase Storage bucket, creating low-resolution thumbnail equivalents to optimize loading performance.

### 5. `image-processing`
* **Purpose**: Extracts image geometries and dimensions.
* **Usage**: Parses EXIF data, orientation coordinates, and image dimensions upon media uploads to help the Flutter app prevent layout snapping during loading.

### 6. `notification-trigger`
* **Purpose**: Multi-channel notification queue manager.
* **Usage**: Manages weekly Digests, batch notifications, and broadcasts to user segments.
